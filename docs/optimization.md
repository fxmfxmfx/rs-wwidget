# Проверка оптимизации от 2026-10-19

Сравнение с рендерером версии 3, до оптимизации. Оформление, размеры,
сетка 16 px, интервал опроса 5 секунд и защита от зависшего захвата сохраняются.

## Изменения

- Часы перерисовываются при смене отображаемой минуты/даты, календарь — даты.
- Системный блок обновляется при изменении данных, включая дробные значения полос.
- PangoLayout используется повторно внутри кадра. Кэш содержит только два описания
  шрифта; дополнительных постоянно хранимых изображений нет.
- Во время переноса повреждаются прежняя и новая области предпросмотра.
  Внутри одной клетки сетки новые кадры не запрашиваются. Линии сетки строятся
  только в пределах ограничивающей области Cairo clip.
- Из `/proc/stat` читается только первая строка, в ограниченный стековый буфер.
- `status.json` содержит накопленное время CPU и монотонное время работы в микросекундах.

## Отрисовка

`tests/render_reference.h` содержит независимый сохранённый рендерер версии 3.
Проверка сравнивает исходные ARGB-пиксели всех блоков и последовательности
полных/частичных кадров сетки при масштабе 1× и 2×. Совпадение точное.
Данные включают календарь високосного года и недоступные показатели системы.

`./build.sh --benchmark` измеряет CLOCK_PROCESS_CPUTIME_ID. Медианы трёх локальных
прогонов (миллисекунды CPU):

| Нагрузка | Версия 3 | После оптимизации |
| --- | ---: | ---: |
| Отрисовка 20 условных минут с опросом раз в 5 секунд | 107,0 | 20,0 |
| Те же перерисовки без сокращения их количества | 107,0 | 90,9 |
| Перенос: 120 кадров при 1920×1080 | 441,7 | 43,0 |

Абсолютные результаты зависят от окружения. Это тест собственно отрисовки,
не процент загрузки CPU работающего рабочего стола. Он не учитывает композитор,
обработку событий GTK и чтение показателей. Нельзя переносить эти коэффициенты
на суммарное потребление системы.

## Работающий процесс

До обновления сохранён замер версии 3: примерно 38,5 MiB RSS и 11,6 MiB PSS.
После перезапуска версии 4 пользователь подтвердил сохранение оформления
и работающее перетаскивание. Через минуту: 38,6 MiB RSS и 11,49 MiB PSS.
Существенного сокращения памяти не наблюдается; основной выигрыш — в объёме
перерисовки и процессорном времени.

По двум снимкам одного процесса между 5-й и 60-й секундами работы:
7 097 микросекунд CPU за 55,002 секунды, около 0,0129% одного ядра.
В этом интервале новых переносов в журнале нет. Это один короткий локальный
замер; прямого измерения CPU предыдущей работающей версии нет.
RSS/PSS не выводятся из бенчмарка рендерера. Текущие значения доступны командой
`~/.local/bin/desktop-widgets status`.

Доля одного ядра CPU между двумя снимками одного PID:

```text
100 × (cpu_usec_2 − cpu_usec_1) / (elapsed_usec_2 − elapsed_usec_1)
```

ASan/UBSan для парсера и загрузчика CPU прошли с отключённым LeakSanitizer:
проверка утечек в среде выполнения недоступна из-за ограничения ptrace.
